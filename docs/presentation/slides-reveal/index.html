Chapter 1

The problem

Weekly status reports are rebuilt by hand, from scattered inputs, for channels that each want a different format.

↓ 2 slides below

[0:15] [Advance. Nothing to say.]

The problem

Three inputs, three channels, one ambiguity

Inputs

Scattered

Notes in a doc, numbers in a spreadsheet, a screenshot in a chat thread.

Channels

Each wants its own format

Email renders HTML, chat wants plain text, a slide wants an image.

Numbers

Easy to state wrongly

“+12%” can mean twelve percentage points or a twelve percent change. Different claims.

[0:15] Status updates come from notes, spreadsheets and screenshots. Each channel wants a different format. And “plus twelve percent” can mean two different things.

What it does

Three kinds of input, one kind of output

  • Progress notes, metrics and images, in any mix
  • AI drafts cards from notes or an image, for review
  • Live preview, rendered by the server
  • Share one card or the whole report; drafts survive a reload
[0:40] So: three inputs, one kind of card. AI drafts, a person reviews. Share one card or the whole report.

Chapter 3

Design decisions

Where the AI stops, how it reads images, the one calculation the tool makes, and why every export matches the preview.

↓ 6 slides below

[5:05] [Advance. Nothing to say.]

AI assistance

The AI drafts. The person decides.

The model never sets the status

Create stays disabled until the person picks one.

Every draft is flagged for review

With a list of what the model could not confirm.

Metric cards are opt-in

Each proposal starts unticked.

Rules and notes travel apart

Prompt in instructions, notes in input, strict JSON schema out.

[5:05] The AI drafts; the person decides. The model never sets the status. Every draft lists what it could not confirm. Metric proposals start unticked.

The boundary

The model copies numbers. It never derives them.

The notes said

“New users: 847, up 23% from last sprint.”

The live model wrote

“…does not provide the previous new-user count; previous is therefore null.”

847 ÷ 1.23 ≈ 688 is a number the notes never state. It appears nowhere in the output, and a browser test asserts that it never does.

[5:35] The rule is not “no numbers”. It is “no invented numbers”. A test checks that 688 never appears.

Reading images

A screenshot is often all someone has

Two ways in

An image with the notes drafts a progress card. On an image card, AI drafts its alt text and caption, so a chart survives a text export.

The one exception to “images stay local”

Sent only on request, after the image is shown, as a JPEG of at most 1024 px. Never stored or logged.

Same rules as text

Copy what is visible, never calculate; text inside the image is data, not instructions.

[5:50] An image can go with the notes, or on an image card. It leaves the browser only when you ask, as a small copy, and is never stored.

The finding

The model misread small print, and did not say so

Label on the chartWhat the live model wrote
$1644.0k$1464.0k, $1464.0k, $1044.0k
$2466.0k$2496.0k, today, while making this slide

Wrong digits in most runs, usually with no review note; once it claimed it had “copied exactly”. A stricter prompt helped one time in three.

So the page, not the model, lists every figure it drafted, and Create waits until the person has checked them.

[6:10] This is my key finding. On tiny labels, the model read 1644 as 1464, and 2466 as 2496, with no warning. So the page, not the model, lists every number, and a person must check them before the card is created.

Metric cards

The one place the tool does arithmetic

67% → 79% is +12 percentage points and +17.91% relative change. Both shown, each named.

A pure function on the server, covered by an 11-row table: zero baselines, negatives, decimals, non-finite input.

DecisionWhy

Chapter 5

Security

Public, no login, and every AI call costs money. So the question is what an attacker would try, not what the tool does.

↓ 3 slides below

[7:35] It's public, with no login, and every AI call costs money. So I looked at it like an attacker.

Threat model

What an attacker would try, and what stops it

AttackControl
An endless request bodyCounted as it arrives; 413 at 64 KiB (1.5 MiB with an image)
One visitor using up the AI for everyonePer client: 6 a minute, 1 in flight
Many addresses running up the billApp ceiling: 30 a minute. Azure deployment capped at 10K tokens a minute
A spend spike nobody noticesAzure alert emails me over 200K tokens in an hour
A forged X-Forwarded-ForOnly the address the Azure ingress appended counts
Script injectionAutoescaping, text-only insertion, CSP script-src 'self'
Prompt injection, in text or an imageRules and content sent apart, strict schema, no tools, human review
A stolen keySecret reference; never in the image, the page or an error
[7:50] Nothing is stored on the server. The real risks are memory, cost, and injected script. Each has a control.

Cost controls on Azure

Layers between an attacker and the bill

LayerWhat it doesStatus
App rate limit6 a minute per visitor, 30 in totalDone
Azure deployment cap10K tokens a minute, down from 100K; holds even if the app is bypassedDone
Cap reachedShown as “busy, try again in a minute”, not “unreachable”Done
Token-usage alertEmail when usage passes 200K tokens in an hourDone
Subscription spending limitCredit exhausted stops resources; no card is chargedOn
Budget alertMonthly budget with email at 50, 80 and 100%Next
Front Door WAFPer-IP rate rules at the edge; from about $35 a monthProduction
[8:10] Cost has layers: a per-visitor limit in the app, a hard token cap on Azure, and an email alert. A budget alert and a WAF come next.

Configuration

Nothing about the model is hard-coded

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env", extra="ignore")

    ai_enabled: bool = False
    azure_openai_api_version: str = "2025-04-01-preview"
    # On a reasoning model this budget covers reasoning
    # tokens as well as the answer: measured against
    # gpt-5-mini, 900 was spent entirely on reasoning
    # and returned an empty, incomplete response.
    ai_max_output_tokens: int = 2_000
    # "minimal" 2.3s, "low" 4.4s, model default 11.6s.
    # All three extracted the same facts, so this
    # defaults to the cheap end.
    ai_reasoning_effort: str = "low"
  • One Settings class, read once; .env.example documents every variable
  • Safe default: AI off, the app still works, the AI endpoint returns 503
  • Each default carries the measurement behind it
  • The key is a Container Apps secret reference; a check fails if it is a literal or appears in the page
  • Dependencies locked; vendored browser files listed with version, source, licence and sha256
[10:05] One settings class. Nothing about the model is hard-coded, and each default records why.
